## Overview

The database is **PostgreSQL 15+** hosted on Supabase. All tables have Row-Level Security (RLS) enabled. The schema has evolved through 22 migration files.

Monetary values are stored in **integer cents** (smallest currency unit). `1000` = KES 10.00. Prices in API responses and export functions are divided by 100 before display.

## Tables

### `categories`
**Purpose:** Menu categories for grouping menu items.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | SERIAL | PK | Auto-incrementing identifier |
| `name` | TEXT | NOT NULL | Category name (e.g., "BBQ Specialties") |

### `customers`
**Purpose:** Customer registry built automatically from phone numbers.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | SERIAL | PK | |
| `name` | TEXT | nullable | Customer name (from checkout form) |
| `phone` | TEXT | UNIQUE (after fix migration) | Kenyan format: 254XXXXXXXXX |
| `email` | TEXT | UNIQUE | Optional email |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | |

**How Created:** Automatically created or updated by `create_order()` RPC using `ON CONFLICT (phone) DO UPDATE`.

**Important:** The `UNIQUE` constraint on `phone` was added in migration `20260624_fix_customer_phone_unique.sql` to fix a race condition where concurrent payments from the same phone could create duplicate customer records.

### `orders`
**Purpose:** Order records, created atomically when M-Pesa payment succeeds.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | SERIAL | PK | |
| `customer_id` | INTEGER | FK → customers.id | Customer who placed order |
| `table_number` | TEXT | FK → tables.table_number | Table identifier |
| `status` | TEXT | NOT NULL, DEFAULT 'Pending' | Order lifecycle status |
| `subtotal` | INTEGER | NOT NULL | Sum of item prices (cents) |
| `total` | INTEGER | NOT NULL | Final total (cents) |
| `payment_status` | TEXT | DEFAULT 'Pending' | Payment state |
| `payment_method` | TEXT | nullable | 'mpesa', 'cash', etc. |
| `notes` | TEXT | nullable | Special instructions |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | |
| `updated_at` | TIMESTAMPTZ | DEFAULT now() | Updated by trigger |

**Status Values:** `Pending`, `Preparing`, `Ready`, `Completed`, `Cancelled`

> ⚠️ **Important:** Status uses PascalCase (not lowercase). This was standardized in migration `20260625`. The `record_order_revenue()` trigger checks for `'Completed'` (capitalized) to fire.

**Indexes:**
- `idx_orders_status` (on status for filtering)
- `idx_orders_created_at` (DESC for recent-first queries)

**Trigger:** `trg_record_order_revenue` — fires `AFTER UPDATE` when status changes to `'Completed'`, inserts a revenue record into `financial_transactions`.

**RLS Policies:**
- `SELECT`: Authenticated (admin/cook see all; waiter sees all via policy)
- `INSERT/UPDATE`: Via RPC only (`create_order`, `update_order_status`)
- Admin can update via the `update_order_status` RPC

**Source:** `20250408_initial_schema.sql`, `20260625_critical_concurrency_and_standardization.sql`

### `order_items`
**Purpose:** Line items belonging to an order.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | SERIAL | PK | |
| `order_id` | INTEGER | FK → orders.id, NOT NULL | Parent order |
| `menu_item_id` | INTEGER | FK → menu_items.id, NOT NULL | What was ordered |
| `quantity` | INTEGER | NOT NULL, DEFAULT 1 | How many |
| `price` | INTEGER | NOT NULL | Price at time of order (cents) — snapshot |
| `notes` | TEXT | nullable | Special preparation notes |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | |

**Design Decision:** `price` is snapshotted at order time, not read from `menu_items`. This means price changes don't retroactively affect completed orders.

**Performance:** Order items are bulk-inserted in a single SQL statement in `create_order()` (via `INSERT INTO ... SELECT FROM jsonb_array_elements()`).

**Source:** `20250408_initial_schema.sql`, `20260624_stats_rpc_and_bulk_inserts.sql`

### `mpesa_transactions`
**Purpose:** Full audit log of every M-Pesa payment attempt.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | SERIAL | PK | |
| `phone_number` | TEXT | NOT NULL | Payer phone in 254XXXXXXXXX format |
| `amount` | INTEGER | NOT NULL | Amount charged (cents) |
| `table_number` | TEXT | nullable | Table reference |
| `checkout_request_id` | TEXT | NOT NULL | Daraja CheckoutRequestID |
| `merchant_request_id` | TEXT | NOT NULL | Daraja MerchantRequestID |
| `mpesa_receipt_number` | TEXT | nullable | Safaricom receipt (on success) |
| `transaction_date` | TIMESTAMPTZ | nullable | When Safaricom processed it |
| `result_description` | TEXT | nullable | Daraja result message |
| `status` | TEXT | CHECK constraint | `PENDING`, `COMPLETED`, `FAILED`, `CANCELLED` |
| `items` | JSONB | nullable | Snapshot of cart items |
| `order_id` | INTEGER | FK → orders.id | Linked order (on COMPLETED) |
| `raw_callback_payload` | JSONB | nullable | Full Safaricom callback payload |
| `cancelled_at` | TIMESTAMPTZ | nullable | |
| `idempotency_key` | TEXT | Partial UNIQUE INDEX | Client-generated dedup key |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | |
| `updated_at` | TIMESTAMPTZ | Auto-updated by trigger | |

**Idempotency Index:** `UNIQUE (idempotency_key) WHERE status IN ('PENDING', 'COMPLETED')` — allows the same key to be reused after a FAILED transaction.

**Auto-update trigger:** `handle_updated_at` using `extensions.moddatetime`.

**Indexes:**
- `idx_mpesa_transactions_phone_number`
- `idx_mpesa_transactions_status`
- `idx_mpesa_transactions_created_at DESC`
- `idx_mpesa_transactions_order_id WHERE order_id IS NOT NULL`

**Source:** `20250409_mpesa_transactions.sql`, `20260311_mpesa_hardening.sql`, `20260624_add_mpesa_idempotency_key.sql`, `20260625_critical_concurrency_and_standardization.sql`

## RPCs (Database Functions)

### `create_order(p_customer_name, p_customer_phone, p_table_number, p_items)`
- **Returns:** `INTEGER` (order ID)
- **Purpose:** Atomically creates customer, order, and order items in a single transaction
- **Security:** `SECURITY DEFINER` — runs as the function owner, bypassing RLS
- **Performance:** Uses single bulk INSERT for order_items (migration `20260624`)
- **Called by:** `complete_mpesa_payment()` RPC

### `update_order_status(p_order_id, p_status)`
- **Returns:** `BOOLEAN`
- **Purpose:** Updates order status, triggers revenue recording trigger
- **Called by:** Kitchen dashboard, admin orders table

### `complete_mpesa_payment(p_checkout_request_id, p_receipt_number, p_transaction_date, p_phone_number, p_result_desc, p_raw_payload)`
- **Returns:** `JSONB` — `{already_completed: boolean, order_id: integer}`
- **Purpose:** Atomic, idempotent payment completion. Locks transaction row with `FOR UPDATE`, checks idempotency, creates order, updates transaction.
- **Called by:** `mpesa-callback` Edge Function (on success), `mpesa-reconcile` Edge Function

### `fail_mpesa_payment(p_checkout_request_id, p_result_desc, p_raw_payload)`
- **Returns:** `BOOLEAN`
- **Purpose:** Atomically marks a transaction as FAILED. Idempotent — returns false if already in terminal state.
- **Called by:** `mpesa-callback` (on failure), `mpesa-reconcile`

### `has_role(_user_id, _role)`
- **Returns:** `BOOLEAN`
- **Purpose:** Stable, security-definer role check function used in all RLS policies
- **Called by:** All RLS policies, `export-financial-data` Edge Function

### `get_dashboard_stats()`
- **Returns:** `JSONB`
- **Purpose:** Single server-side aggregation query returning all KPI stats (active orders, today's completions, revenue, trends). Replaces multiple frontend queries with one efficient DB call.
- **Called by:** `useStatsCardSummary` hook

### `set_user_as_admin(user_email)`
- **Purpose:** Utility function to promote a user to admin by email
- **Called by:** Admin user management workflow

### `handle_new_user()`
- **Type:** Trigger function
- **Purpose:** Fires on `auth.users` INSERT to create profile and assign default role

## Triggers

| Trigger | Table | Event | Function |
|---------|-------|-------|----------|
| `trg_record_order_revenue` | `orders` | AFTER UPDATE | `record_order_revenue()` — inserts revenue on Completed |
| `trg_record_manual_sale` | `manual_sales` | AFTER INSERT | `record_manual_sale_revenue()` — inserts revenue entry |
| `trg_record_refund` | `refunds` | AFTER INSERT | `record_refund_transaction()` — inserts refund entry |
| `handle_updated_at` | `mpesa_transactions` | BEFORE UPDATE | `extensions.moddatetime(updated_at)` |
| `on_auth_user_created` | `auth.users` | AFTER INSERT | `handle_new_user()` |
